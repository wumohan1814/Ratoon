# engineering-principles

> 版本：v1.0 ｜ 状态：待命中

## 一句话
跨项目的**工程准则**：架构准则 18 条 + 开发/协作纪律 10 条 + Agent 运行成本纪律。新项目建项后可作为项目自己的准则基线。

## 不解决什么（边界）
- **不管流程/框架**——流程归破竹协议（`00_协议`–`04`）；本资产只管**技术架构与工程纪律**
- 已**剔除**首实例（taichu）时代的内容：台账状态机 🟡🔵🟠🟢 / REQ·BUG 编号 / 三角色与测试组 / supersede 口径 / 交付物中心——**破竹框架下不适用**（以免污染新项目）
- **不规定技术栈**（与破竹 §6 一致：技术栈由项目自定）

## 契约（用之前必须知道的）
- 怎么调用：**复制**本目录 `准则.md` 到项目自己的准则位置，按项目实际增删
- 依赖什么：无（纯文档资产）
- 什么绝对不能改：无硬约束；改动须记 `变更记录.md`

## 用过的项目
见 `库/索引.md`（爆炸半径唯一记录处）。

## 已知限制 / 坑
- 架构准则按"技术无关"表述，落地方式因技术栈而异（如"常驻服务"在无服务形态下不适用）
- 成本纪律假设**自治 Agent 模式**；传统"人 + 助手"模式部分条目不适用
- 条目附"检查项"是**验收可用**的，建议直接抄进项目验收清单
