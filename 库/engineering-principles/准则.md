# 工程准则（跨项目通用）

> **来源**：首个破竹实例 taichu 的项目准则（v5，2026-09-11）；本资产为**已剥离版本**——剔除了破竹框架下不适用的内容（台账状态机 🟡🔵🟠🟢 / REQ·BUG 编号 / 三角色与测试组 / supersede 口径 / 交付物中心）。
> **用法**：新项目建项后，把本文档抄进项目自己的准则位置，按项目实际增删条目；每条末附"检查项"，可直接抄进验收清单。
> **冲突优先级**：用户口头指令 > 本文档 > 项目文档。

## A. 架构准则（18 条 · 按技术无关表述）

| # | 准则 | 检查项 |
|---|---|---|
| A1 | **接外部服务先做"最小真调冒烟"**：新接 LLM / 第三方服务 / 库，第一动作是真调一次、逐字段核对响应结构，再写解析层 | 解析函数有关键字段回退；冒烟用例覆盖结构差异 |
| A2 | **重试与失败：硬上限 + 快速失败**：重试次数设硬上限；对"连续 N 次同类错误"判服务不可用、立即停并标记失败；失败原因落错误字段供前端展示 | 重试上限可配置；有连续失败快速中止；失败态展示可读原因 |
| A3 | **计费/成本口径先于用量统计**：接入前确认完整计费口径（字段、缓存命中、峰谷、并发上限）；成本口径必须含"辅助调用" | usage 含缓存命中字段；成本脚本支持峰谷；单价可配置 |
| A4 | **确定性计算先行，LLM 只保留必要步骤**：每个 feature 先答"能否确定性计算 + 内置文案" | 有确定性方案段落；每个 LLM 调用点接计量与扣费 |
| A5 | **用户可见数据要检查本地化/结构**：第三方库产出的用户可见文本，接入后遍历输出字段抽检语言 | 用户可见字段一致性抽查；对残留有映射表 |
| A6 | **跨源聚合必须有归一化层**：凡"把异构来源归并为有限类别"处都要有归一化映射；要模型产出多样化时，prompt 显式要求 + 代码层兜底归并 | 聚合前有归一化；验收时核对输出类别是固定集合 |
| A7 | **框架性文字放 UI 层，不混进数据**：免责 / 版本号 / 水印等由 UI 统一组件渲染，数据字段保持纯净 | 内容字段不含框架文字 |
| A8 | **配置 / 常量名显式映射**：字段名含"缩写拼接"可能映射错 → 显式别名映射 + 本地断言 | 新增配置字段必写显式映射 + 断言；部署后双重核对 |
| A9 | **路由 / 回退保留后端语义**：静态 SPA fallback 必须排除后端路由前缀的 404 语义；静态资源一律根绝对路径 | fallback 排除所有已注册前缀；非法 key 返 4xx 而非 200 HTML |
| A10 | **幂等 + 缓存命中是数据型功能的默认设计**：多入口触发同一逻辑实体 → 默认幂等键 + 缓存复用；**幂等拦在任务入口**（先查 running/pending 再建，返回既有 id） | 新增创建型接口先答"重复调用会怎样" |
| A11 | **单一事实源**：任何"形态 / 状态"只允许一个权威声明；发现冲突当场标"以 X 为准"，不静默 | 权威运行件写入文档；文档引用的文件实际存在 |
| A12 | **长任务四件套**：可轮询状态 / 进行中任务复用（幂等）/ 重启后恢复（已完成子步零成本复用）/ 按子步计量 | 重复点击只建一个任务；已成功子步重跑不重复扣费 |
| A13 | **常驻服务 + 保真降级链**：高复用重依赖走常驻；保留降级路径；分层各自容错（正确性优先、不阻断主链） | 重依赖常驻化；降级路径字节级保真；任一层失败自动回退并告警 |
| A14 | **选库先盘点仓库现成能力**：引入外部依赖前先盘"已在仓库里的能力"；外部库只按**增量缺口**引入，差集为空则跳过并留档理由 | 列出现有能力清单；每个候选标注差集；跳过写理由 |
| A15 | **数据迁移与保留字（老库路径测试）**：新列/表名先查目标库保留字；**迁移测试必须覆盖"既有 schema + 增量 ALTER"**（不能只测新建库——ORM 建新库会自动加引号，掩盖裸 SQL 问题） | 新列名无保留字；有老库迁移回归用例；部署前用"已有库"冒烟迁移 |
| A16 | **并发改造前置：审计共享可变状态**：先开"共享可变状态清单"（全局变量 / session / 账本 / 计数 / 自增列），逐项写隔离策略；数据库并发写先开 WAL + busy_timeout；"查缓存 → 落库"必须原子或幂等 | 并发改造前清单逐项过；计费/计数/幂等不依赖未隔离的模块级状态 |
| A17 | **阶段式长流程：后端显式状态字段**：每阶段完成时写显式状态字段；前端主按钮按状态机分支导航，**不用计数/布尔近似推断阶段** | 每阶段完成同步后端状态；主按钮穷举全部状态分支 |
| A18 | **发布与运行环境（本地 ≠ 生产）**：不进 git 的构建产物必须**显式进镜像或构建期生成**（.gitignore 排除会悄悄丢运行时依赖）；环境差异（DNS / 时区 / 跨境网络 / 容器 DNS ≠ 宿主机）先探测后部署 | 部署前核对镜像依赖清单；目标机实测 DNS/上游连通 |

## B. 开发与协作纪律（10 条）

| # | 准则 | 检查项 |
|---|---|---|
| B1 | **委托实现**：架构 / 契约 / 拆分 / 审查 / 验证归负责人，底层代码实现委托子代理。"别人生产了元素" ≠ "已落地代码"——拿到交付文档先列**责任矩阵**（已入库 / 待我实现 / 待他人实现），歧义先问 | 负责人不手写底层实现；不 busy-poll（等完成通知） |
| B2 | **子任务 spec 四要素**：①目标文件清单（含**禁碰清单**）②验收标准（含"不改什么"）③验证命令（要求贴输出）④commit 消息模板 + push 禁令；spec 给足**代码坐标**（文件/行号/符号）；大单文件每批 ≤2 项 | spec 模板含"不触碰文件清单" |
| B3 | **提交纪律**：小步提交（每完成一批即 commit）；**只 add 本任务文件**（显式 pathspec），**绝不 `git add -A`**；commit 前核对 `git diff --cached`（stat + 抽样），发现错标（误装他人未提交内容 / 消息与内容不符）**立即 `--amend` 如实汇报，不掩饰** | 每个 commit 前 `git status` + staged diff 核对 |
| B4 | **子代理卡死与停滞预案**：监控产物 mtime → 判卡死 → `interrupt` → 给"精确位置 + 期望形态 + 验证命令"，**不整任务重派**；**停滞阈值 >10–15 分钟零写盘**；中断前确认磁盘无半成品 | 卡死的局部 bug 优先精准指引；大任务先试点小批 |
| B5 | **子代理失败诊断与收口**：默认继承主会话配置（不手动指定模型）；连续失败且零产出 → 先诊断路由/环境/余额，不盲目重试；**半成品可收口**（主 Session 复跑门禁）vs **零产出**（诊断后重派）；**通道失败 → 轮换通道** | 连续失败先查路由/余额/环境；spec 不强制指定模型 |
| B6 | **大工程拆分与并行边界**：**并行边界 = 文件所有权不相交**；后端多文件可并行，**前端单文件永远是流水线**；同文件子任务**强制串行**（回报 → 验证 → commit → 才派下一个）；每批验证四件套 = `diff --stat` → hunks 核对越界 → 残留标识符 grep → 门禁 | 派发前画"任务 → 文件"矩阵确认无交集 |
| B7 | **部署与高风险操作纪律**：失败先看进程/容器状态 + 日志定位根因，不猜；**验证链** = health + 页面 200 + 进程稳定（无重启循环）+ 关键接口冒烟 + 线上 commit 核对；**走公网真入口 + 新版特征断言**（镜像内常无 .git，git 内省不可用）；数据修复与代码修复**分轨**；能锁死的操作先备逃生通道 + 备份；服务器配置必须进 git；**小内存主机（≤2G）构建必须限流**（`--memory`）+ 后台日志轮询（间隔 ≥45s）；云主机自动配置会覆盖手改（如 cloud-init）→ 禁用其接管 + 重启后复验；**跨 shell 远程命令统一 ASCII**、复杂内容 base64 传输 | 部署脚本带产物验证与限流参数；异常先看日志；重启后复验关键配置 |
| B8 | **存量大范围改造（增量推进 + 兼容别名）**：禁止一次性全量迁移 → 分阶段"建体系 + 新功能遵守 + 存量按模块迁"；数据与代码分离；迁移期给**兼容别名**；"结构先上、正文后补"必须登记显式跟踪项 | 新内容走新体系；占位符/空表清单清零或有排期 |
| B9 | **工具化分工：确定性交程序，判断归 Agent**：切字段/解析/生成/校验/格式化等确定性输出由程序完成，Agent 只读产物做判断（不用 LLM 做确定性生成）；**"结构化 ≠ 双份事实源"**——要看板/CSV 就从唯一事实源**派生只读产物**（带生成时间戳 + 一致性校验），产物标"勿手改" | 源改后跑派生脚本；产物含时间戳；校验警告为 0 |
| B10 | **诚实声明能力边界**：明确说清能做什么、不能做什么（尤其日志/运行态/成本/外网/真机浏览器等实时信息），不假装看见；环境约束前置声明并约定分工 | 关键处（成本/日志/运行态/权限）主动声明边界 |

## C. Agent 运行成本纪律（Token 经济）

> **适用前提**：项目采用**自治 Agent 模式**（主 Agent + 子代理 + 并行 Session 全自动跑完软件工程）。此模式下 token 消耗与"人 + 代码助手写 MVP"**不是一个量级**——模式使然，但必须被治理。

### C1 成本结构（四层）
1. **主会话上下文回放（大头）**：每轮工具调用携带完整历史；常驻大文档反复全额读入；**会话不收敛 → 越到后面每轮越贵**
2. **子代理**：每个子代理独立上下文；**用"继承主会话上下文"的通道时，每次启动还回放主会话全部历史**
3. **并行 Session**：每个并行角色独立消耗
4. **反复重试与循环**：每次失败 = 全量上下文回放 + 新输出

### C2 降本纪律（7 条）
1. **会话收敛**：里程碑/阶段结束就开新会话；跨会话上下文由落盘文档承接
2. **大文件纪律**：禁止整文件通读——先 grep 定位锚点再只读命中行；spec 直接给文件/行号/符号
3. **子代理通道**：优先用**独立上下文**的通道；通道不可用要修，不将就
4. **失败先诊断再重试**：先判类型（半成品可收口 / 环境问题 / 契约不符）再动手
5. **常驻文档精简**：每轮注入的守则/速览/索引越长，累计成本越高——定期瘦身，只留"必须每轮知道"的
6. **并行按需**：并行 Session 只在真正独立的活上开，能串则串
7. **精确计量交给账本**：用量与成本以厂商账单/usage 账本为准，不靠感觉估

- 检查项：里程碑收尾是否开了新会话；大文件是否走 grep → 精准 read；失败是否有诊断记录而非连续重试；成本结论是否引用账本而非估算
