# 阶段③ 收尾（模块入口 · **总流程**）

> **何时启用**：用户说"做完了 / 想上线 / 想开源 / 要交付"。
> **之前它不在框架里**（v0.30 首次建立；v0.34 按用户给的四项需求定稿）。

---

## 加载规则（**重要**）

- **只加载本模块 + 共享核心**；**不加载** `阶段①_构思/`（阶段之间互不加载）
- **共享核心**：`00_协议.md` · `00_根/` 结构 · `库/`
- ✅ **本模块不进每轮注入层** → **它写得比别处细，不影响开发阶段的 token 成本**

---

## 收尾四步（**顺序不能反**）

| 序 | 步 | 文件 | 为什么在这个位置 |
|---|---|---|---|
| **1** | **交付前检查** | `交付前检查.md` | **不可逆的必须先做**——发布后才发现违规 / 密钥泄漏 = **收不回** |
| **2** | **README 与发布** | `README与发布.md` | 对外说明 + 元数据位；**许可结论来自第 1 步** |
| **3** | **项目复盘** | `项目复盘.md` | 初衷 vs 现状（**初衷 = 阶段① 写进 `入口.md` 的那一段**） |
| **4** | **归档与封存** | 走一遍 `01` §7（裁决与清理）+ 结构可读化；状态写进 `99_状态/` | 让项目有个**干净的终点** |

**第 5 件（贯穿全程）**：**判断是否上传 GitHub / 开源**——决定项目形态的**单向门**。

- **判据**：用户的目的（自己用 / 给别人用 / 想被看到 / 想让人改）
- **归用户拍板**，Agent 只给后果。**话术与选项不在这里重复**——见 `交付前检查.md` §2.2 的许可选项表（两者常常是同一个决定）

---

## 用户在这一阶段要做的决定（**只有 4 个**）

| 决定 | 归谁 |
|---|---|
| **许可证选哪个**（含"暂不选"） | **用户**（Agent 给后果表） |
| **要不要上传 GitHub** | **用户** |
| README 里"做到了什么"**是否属实** | **用户核对**（Agent 写，凭来自 `40_节/完成/`） |
| 复盘后的 1–3 条建议**接不接受** | **用户** |

> 其余全部由 Agent 做完。**用户在这一阶段仍然是"只做决定"**。

---

## ⛔ 边界（v0.32 用户明确）

本阶段**只帮用户把"项目开发本身"收尾**——
**不涉及商业化**：不写宣传文案、不做营销方案、不帮拉投资、不做商业计划。
**判断依据**：破竹管的是「**把想法变成可执行的项目**」，不管「把它变成生意」。

---

## 与其他阶段的关系

| 阶段 | 它已经产出的东西，收尾期要用 |
|---|---|
| ① 构思 | **`00_根/入口.md` 的「为什么做」**（复盘唯一的比对基准）· 蓝图（"离成品还差多少"的基准） |
| ② 开发 | `00_根/来源.md`（第三方内容登记）· `00_根/全貌.md`（产品的全貌）· `40_节/完成/`（做过什么、凭在哪） |

> **关键**：**合规检查的数据来源是开发期登记的 `来源.md`**——所以**登记必须在开发期做**（用的时候记），
> **不能等上线才回想**（回想必然漏，而且那时已经太晚）。
> **同一条原理也适用于"初衷"**——所以它在**阶段①**就被记进 `入口.md`（`00` §7 第 1 问）。
