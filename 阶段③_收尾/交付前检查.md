# 交付前检查（阶段③ · **第 1 步**）

> **触发**：用户说"要上线 / 要开源 / 要交付"，**或**一个阶段性任务交付前。
> **为什么它不可省**：**一旦发布，问题无法收回**（与 `01` §9.1 判据 3「埋点」同类——防的是**不可逆损失**）。

---

## 〇、开发收尾完整性（先确认，再往下走）

| # | 检查 | 通过 = |
|---|---|---|
| 1 | 节编号连续 | `40_节/完成/` + `待办/` + `_archive/` 的**文件名并集**无缺号（缺号 = 有节开着没收；只列文件名，不读归档内容） |
| 2 | 入口最新 | `入口.md` 的「当前形态」「下一步」已更新到最后状态 |
| 3 | 无半截节 | `40_节/待办/` 已清空（或剩下的都是明确"未开始"的） |

> 任一条不过 → **先回阶段② 收尾**，不要带着半截状态做发布。

## 一、第三方内容合规（**用户完全看不见的那一类**）

### 1.1 数据来源

**唯一来源 = 开发期登记的 `{{项目}}/00_根/来源.md`**。
**所以登记必须在开发期做**（用的时候记）——**等上线才回想，必然漏。**

> ⚠️ **破竹自己**（本框架仓库）**没有 `00_根/`**——它的来源登记已并入 `README.md` 的「**致谢 / 参考来源**」。

### 1.2 逐条过来源表，每条给一个**大白话结论**

| 结论 | 什么情况 | 上线要求 |
|---|---|---|
| ✅ **可以直接用** | MIT / Apache-2.0 / BSD 等宽松许可 | README 里**保留原版权声明**（多数要求） |
| ⚠️ **要署名 / 要开源** | MIT、Apache-2.0、CC-BY；**GPL 类**（传染：用了它你的项目也要开源） | README 写明来源 + 许可；**GPL 类要特别确认能否接受** |
| ⚠️ **改动程度影响结论** | 只借用"思路/形态"通常不算复制（**但要看具体许可证**）；直接复制代码/素材则必须遵守 | 逐条判断"是参考还是复制" |
| 🚫 **不能用** | **未标注许可证**（= 默认保留全部权利）· 商业授权不明 · 明确禁止商用 | **替换掉 / 重写 / 联系作者取得许可** |
| 🚫 **去痕 ≠ 合法** | **删除原作者版权信息不能摆脱许可证** | 明确写出这一点 |

### 1.3 ⚠️ 三个必须主动说的"小白陷阱"

> **Agent 必须主动提**（用户不知道自己不知道）——这是 `02` §7.2「主动提代价选项」的应用。

| 陷阱 | 大白话解释 |
|---|---|
| **"没写许可证 ≠ 随便用"** | 没写 = **默认保留全部权利**，不能复制。**这是最常见也最危险的一个。** |
| **"改了就不算"** | 大改**不改变**许可证义务——尤其是 GPL 类；删掉版权声明更是**加重**问题 |
| **"只有我一个人用所以没事"** | **一旦公开部署/开源/给别人用**，就进入许可证的射程。**私人自用通常不算**——但"上线"就是分界线 |

### 1.4 产出：README 的通报段落

Agent 给用户一段**可直接粘贴的 README 段落**：

```markdown
## 致谢与许可
本项目使用了以下第三方内容：
- {来源项目}（作者，{许可证}）—— {用在哪}；{改动说明，如"仅参考思路"或"复制并遵循其许可"}
- …
本项目自身以 {许可证} 发布。
```

**用户只需决定"接受 / 不接受"**——不需要懂许可证细节。

## 二、项目自己的许可证（**"不写"也是一种选择，而且是坏的那种**）

> **归谁**：**选择归用户**（铁律 1）——Agent 的活是**把后果讲清楚**，不是替他选。
> **为什么必须在这里解决**：它决定"这个项目能不能被别人用"，而这件事**一旦发出去就收不回**。

### 2.1 先纠正一个反直觉的事实（**必须主动说**）

| 用户可能以为 | 事实（[choosealicense.com](https://choosealicense.com/no-permission/)，GitHub 官方维护） |
|---|---|
| "没写许可证，那别人爱怎么用怎么用" | **反了**。作品默认处于**独占版权**下——**没有许可证，别人不能复制、分发、修改** |
| "我放在 GitHub 上公开了，就等于允许用" | 公开仓库只让**查看和 fork**；**这不代表允许使用 / 修改 / 分享** |

**大白话讲法**：「你现在这个项目，**在法律上是谁都不能用**的——包括你想让别人拿去学、拿去改。
你要么明确说"可以，按 XX 的规则"（选一个许可证），要么接受"就是谁都别用"。」

### 2.2 四个选项（**Agent 给这张表，用户拍板**）

| 选项 | 一句话后果 | 适合 |
|---|---|---|
| **MIT** | 谁都能用、能改、能商用，**只要保留你的版权声明** | **想让尽量多人用**（最省心的默认） |
| **Apache-2.0** | 同 MIT，外加**明确的专利授权** | 想防"被拿专利反打" |
| **GPL** | 谁用了你的代码，**他的项目也必须开源**（传染） | 想让"用了就必须回馈" |
| **暂不选** | **别人不能合法使用**（= 事实上的"保留所有权利"） | 还在犹豫——但要清楚这是"**谁都不能用**" |

> **⚠️ 必须说的一句**：选了 MIT / Apache 之后**不能反悔**——已经发出去的副本，别人可以永久按当时的许可用。
> 这是**单向门**（`00` §6）→ **按下去之前，用户必须听懂这一句。**

### 2.3 文档 / 内容类项目另有一套（**CC 系列** · 破竹自己属于这一类）

> **判据**：许可证要匹配**作品形态**。软件用 OSI 系列（MIT / Apache / GPL），**文档与内容用 CC 系列**。
> **破竹本身是规范与文档** → 它在下面这张表里，**不在 §2.2 那张里**。

| 选项 | 商用 | 署名 | 衍生作品 | 是"开放许可"吗 |
|---|---|---|---|---|
| **CC BY 4.0** | ✅ 免费 | 必须 | 随便改 | ✅ |
| **CC BY-SA 4.0** | ✅ 免费 | 必须 | **改了必须也开放**（传染） | ✅ |
| **CC BY-NC-SA 4.0** | ❌ **禁止**（除非另行取得授权） | 必须 | 必须也开放 | ❌ **不是**（歧视领域） |

**两条必须说清的事实**：

- **"商用要付费"的许可，按定义不是开放许可**——[Open Definition 2.1](https://opendefinition.org/od/2.1/en/) §2.1.9「许可**不得**把任何费用安排、版税或其他补偿作为其条件」；[OSD](https://opensource.org/osd) 判据 1、6 同款。
  所以选 NC 必须**诚实标注为"内容可用"，不能自称开源**。
- **要钱，走"服务"而不是"许可"**：CC BY-SA **允许别人商用，但完全不阻止你自己收培训 / 咨询 / 定制的钱**——客户买的是你的时间，不是许可。**这是两条独立的路。**

**若将来接受外部贡献**：贡献者**各自持有自己那部分的版权** → 你就**失去单方面再许可的能力**。
要保留这条路 → **现在就加一句"贡献即授权作者再许可"**，否则以后想改许可得逐个找贡献者同意。

### 2.4 落地三件事

1. 项目根目录放 **`LICENSE`** 文件（用现成模板，**不要手写**）
2. `README.md` 末尾一行：「本项目以 {{许可证}} 发布」
3. 在 `00_根/复盘.md` 或 `99_状态/决策.md` 记一句**为什么选它**（将来你会忘）

## 三、Git 与发布（**"你以为传上去了"的那一类**）

> **Git 机制在阶段② 就建好了**（`03` §5 段二「第 0 步 · Git 由你全包」）——
> **这里不做"建立"，只做"发布前最后一次核对"**。

| # | 检查 | 大白话判据 | 漏了会怎样 |
|---|---|---|---|
| 1 | **有没提交的内容** | "你改过、但没存进历史的东西" | **你以为传上去了，其实没有**——最常发生 |
| 2 | **有没推送的内容** | 本地有、GitHub 上没有 | 电脑坏了就没了 |
| 3 | **密钥 / 凭据有没有进历史** | 过 `02` §10.2 五问；另搜一遍 key/token | **一旦 push，泄漏不可逆** → 必须换 key |
| 4 | **个人信息有没有硬编码在项目里** | 按 `入口.md` 的「个人信息清单」+ 开发期在 `已知问题.md` 记下的清单 + 通用模式（域名 / 服务器 IP / 邮箱 / 手机号）**搜一遍**，有则替换占位符，或问用户是否要公开 | **公开后身份 / 隐私无法收回** |
| 5 | **大文件 / 垃圾有没有进仓库** | 仓库体积 + `.gitignore` 是否真生效 | 历史不可逆，删了仍占体积 |
| 6 | **个人内容与项目内容的边界** | 列出项目里**不属于项目本体**的内容（参考资料 / 调研笔记 / `_archive/` 已归档 / 个人草稿），逐项问用户：一起公开，还是**排除在上传之外**（移出仓库，或加进 `.gitignore`） | 个人资料被公开，收不回 |
| 7 | **回滚预案有没有** | 发布前打一个**稳定 tag** + 记一句大白话"怎么回滚到上一个稳定版本"（用户看不懂 git，出事后 Agent 靠这句兜底） | 发布后出事（严重 bug / 泄漏）无法快速回滚 |
| 8 | **依赖有没有已知漏洞** | 跑一次依赖漏洞扫描（`npm audit` / `pip-audit` / `cargo audit` 等，按技术栈选），有**高危**就报 | 开源后依赖漏洞是最常见攻击入口 |
| 9 | 🔴 **已经 push 出去的敏感内容** | **最后一次能拦的机会** | **唯一真正不可逆的一类**——发布前**必须专门问一次** |

> **"要不要上传到 GitHub"这个决定本身**：话术与判据见 `阶段③_收尾/README.md` 的**第 5 项**
> （**决策归用户**，且是单向门）——**不在这里重复**。

## 四、其他交付前检查（**简版，待首个项目跑完再按需补**）

| # | 检查 | 怎么查 |
|---|---|---|
| 1 | **安全 / 数据** | 过 `02` §10.2 的五问（隔离 / 凭据 / 越权面 / 资金 / 个人信息） |
| 2 | **性能** | 涉及渲染/查询/循环的，测一个数字（`02` §7.1）——**上线前的那一次最重要** |
| 3 | **`.env` / 密钥没有进版本库** | 检查 `.gitignore` + 仓库里没有真实 key |
| 4 | **线上能打开** | 先查 `库/索引.md` 有没有部署验证类资产；有就照它做，**没有就跳过**（不要去找别的项目目录） |
| 5 | **数据备份** | 项目有数据 / 数据库 → 发布前做一次**完整备份**（导出到仓库外，或确认自动备份在跑），并**验证能恢复**（不是只备份不验证） |

**Agent 主动咨询 / 提醒的事项（决策归用户，不做成固定检查）**：

| 事项 | Agent 怎么做 |
|---|---|
| **隐私政策 / 免责声明** | 项目若收集用户数据（邮箱 / 账号）→ 提醒需要隐私政策；README 建议加一句免责声明（"按原样提供，作者不承担损失"） |
| **账单 / 冒烟** | 咨询用户：发布后的运营成本（服务器 / API / 域名）要不要梳理；线上关键路径要不要真跑一遍冒烟 |

## 五、这一阶段的输出（给用户看的）

```
① 合规结论（每条来源：可直接用 / 要署名 / 不能用）
② 许可证结论（选哪个 / 或"暂不选 = 谁都不能用"）
③ Git 结论（有没提交 / 有没推送 / 🔴 有没有已 push 的敏感内容）
④ README 致谢段落（可直接粘贴）
⑤ 发布前必须处理的问题清单（若有"不能用"的）
⑥ 建议：现在发布 / 先处理问题再发布
```

**用户只做决定**：接受 / 不接受 / 先处理哪个。
