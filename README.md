# Ratoon · 破竹

> **让一个完全不懂代码的人，靠 AI Agent 长期维护多个软件项目，而不被三件事拖垮：失忆、返工、账单。**

**中文** ｜ [English](README.en.md)

---

## 这是什么

破竹是一套 **Markdown 协议**（几十个规范文件）——不是代码框架、不是 App、不是工具。它规定的是一件事：

> **一个不懂代码的用户 + 一群 AI Agent，怎么协作把"一个想法"变成"能长期演进的软件项目"。**

核心一句话：**把"一次对话"变成"一节竹子"**——每一节都有边界、有证据、可以停下来。

- 中文名「**破竹**」= 势如破竹，也指竹子一节一节长，每一节都完整、有界、独立。
- 英文名 `Ratoon` = 收割后从根上重新长出的新芽——一个项目做完，下一个从同一套方法上再长出来。

---

## 它解决什么

如果你用 AI 做过个人项目，你一定碰到过这三个坑：

| 痛点 | 破竹怎么治 |
|---|---|
| 🧠 **失忆** | 换会话就忘了做到哪 → 每个项目用**一套文件当持久记忆**（`00_根/` + `40_节/`），新会话靠读文件接手，不靠回放对话 |
| 🔁 **返工** | 改需求就全量回放、来回返工 → **一次迭代 = 一节**，每节各自收尾落盘（一个会话可连续做多节）；靠**复述 + 强度分档 + 往返预算**把理解偏差拦在动手前 |
| 💸 **账单** | 说不清"做完没有"、反复烧 token → **完成 = 交得出真实产物**（用户亲眼看/点/听的东西），不是 Agent 嘴上说"做完了" |

顺带解决第四件事：**跨项目复用**——一个项目里验证过的东西，能带进下一个项目（`库/`），不重复造轮子。

## 快速开始（3 步）

你**不需要懂代码、不需要记任何口令**。开新项目时：

1. 把破竹里的 **`bootstrap.md`** 复制到你**新项目的文件夹**（最外层）。
2. 对 Agent 说：**「读 `bootstrap.md`，按它做。」**
3. 它问"破竹放在哪个文件夹"时，把**破竹文件夹的地址**复制给它（点开文件夹顶部的地址栏 → 复制 → 粘贴）。

之后它会自动：验证能读到 → 把入口写进你项目的 `AGENTS.md` → 执行**构思**（给你一页大白话蓝图）→ 你拍板 → 开始一节一节做。

> 为什么要有这步：换 Agent 工具时，Agent 不会自己去找项目外的协议。`AGENTS.md` 是你的项目自己那份"入口"，换工具也认。

## 日常你只需要做两件事

| # | 做什么 | 怎么做 |
|---|---|---|
| **1** | **说需求** | 说人话就行。Agent 自己识别你处于哪个场景，不懂就回读规范，不用你提醒 |
| **2** | **看产物拍板** | Agent 给你**真实环境地址** → 你亲自打开、点、看 → 说「可以」或「不对」 |

**你不需要**：懂代码、看文件、盯进度。技术选型由 Agent 用大白话说清利弊，**你拍板**。

**出问题时直接说人话**：
- 改坏了 → 「**改坏了，撤销**」（Agent 一句话回退，让你亲眼看恢复后的样子）
- 说不上哪不对 → 「**看着不对，跟上一版比一下**」
- 不知道要做啥 → 「**给我看全貌，哪些还没做**」
- 想法太多很乱 → 「**我有一堆想法，都给你**」

**什么时候该收尾**：你不需要判断——Agent 会主动说「这节验收通过，建议收尾」，你回「要」就行。收尾后 Agent 会问你要不要换新对话：换就把交接词粘进去说「继续」，也可以留在当前对话接着做下一节。

**唯一需要你亲自把关的**：开新项目时的**「蓝图确认」**——Agent 给你一页大白话（含"这个方案最可能怎么失败 + 建议先防哪条"），你看完说「可以」或「不对」。

## 核心设计（给想深入了解的人）

- **事实归 Agent，决策归用户**——能查的一律 Agent 自己查（文件/网络/代码/账单），只把「目标、取舍、口味」摆给用户拍板。
- **单一事实源**——每类信息只有一个权威位置，重复记录 = 缺陷。
- **完成不是自述，是证据**——交不出真实产物 = 没完成，哪怕代码写完、测试跑通。
- **一节竹子**——一次迭代 = 一节，长成一节就可以停（一个会话可连续做多节）。
- **框架自己不能成为成本**——注入层必须短、极少变动；方法来自实测、优先删机制。

三阶段：**① 构思（定方向、蓝图）→ ② 开发（一节一节做）→ ③ 收尾（合规、许可证、发布、复盘）**。

## 已知边界（诚实声明）

破竹是一套**「成本控制 + 真相追踪」协议**，不是一套"工程质量"体系。用它做出来的项目，以下四层需要你自己留意：

- **数据**：协议不自动做数据库迁移 / 备份；有数据的项目请自行备份（发布前尤其）。
- **安全**：协议防"密钥 / 个人信息进仓库"，但鉴权、防注入（SQL / XSS）、CSRF 等需要项目按需加强——**涉及他人数据或资金时尤其**。
- **测试**：验收靠"用户看真实产物"，不强制自动化测试；长期演进的项目建议补回归测试。
- **运维**：发布后没有内置监控 / 告警 / 日志；线上可用性请自行配置。

这些是**设计取舍，不是 bug**——协议把"省钱 + 交真东西"做到了极致，代价是工程质量更多依赖使用者的自觉。重要项目请在对应层面补上防护。
