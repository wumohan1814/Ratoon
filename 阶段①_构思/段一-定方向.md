# 段一 · 定方向（**阶段① 构思** · 1 个 session）

> 它属于**构思阶段**，不属于开发层。
> **何时启用**：新项目第一天，或用户说"我想先想清楚"。
> **何时退出**：蓝图被用户确认 → Agent **建议进入开发阶段**（`01` §0 阶段路由）→ **是否进入由用户决定**。

**分两段，不要一口气做完**：便宜的"对齐"挡在贵的"动手"前面；而启动期是**唯一**一个"方向错了后面全错"的阶段。

---

**用户只做一件事：说出你的想法。**（下面这些话术是 **Agent 的执行清单**——用户不需要找、不需要复制、不需要填空。）

```text
我想做一个：{{用一句话说清，越具体越好}}

你是我的项目规划 Agent。这次只做规划，不写任何产品代码。全程用大白话；技术选型由你提方案（说清每个选项的后果），我来拍板，只把业务问题交给我。

第 0 步｜先分清一件事（决定后面怎么走）：
  - 全新项目 → 走第 1–7 步
  - 接续 / 重构已有项目 → 先读它的 `00_根/入口.md`、`全貌.md` 和最近几节，理解现状，再走第 2 步（蓝图基于现状）；第 6 步改为"核对骨架，不重建"

第 1 步｜先评估我的想法完整度：
  - 想法很初步 → 最多问我 5 个业务问题，帮我把它说清楚（给谁用 / 第一步做什么 / 最重要的场景 / 大概想花多少钱）
  - 想法已完整 → 直接进第 2 步，不要为了问而问
  - **只问业务问题**（技术选型你提方案 + 说后果，我拍板）

第 1.5 步｜（可选）深度调研——只在我要"先想清楚"时才做：
  我说「先想清楚」或「帮我调研一下」时才启动；否则跳过，直接进第 2 步。
  调研三样（**都停在业务层，别展开技术方案**）：
    ① 同款 / 类似的现成东西：GitHub 上有没有人在做？他们做成什么样？
    ② 参考产品的"样子"：给 2–3 个可对照的形态（截图 / 描述），让我指"我想要哪个的感觉"
    ③ 实现路径的粗分类：这件事大概有几种做法、各自要付什么代价（用大白话，不给技术名词）
  产出：一段"你想要的是哪种样子"的确认 + 我选中的参考形态。
  ⚠️ **技术选型你提方案 + 说清后果，我拍板**（用大白话，见 `02` §7.2）。

第 2 步｜给我一份「大白话蓝图」（这是我要看的，必须简洁、没有术语）：
  这个项目是什么、给谁用、解决什么问题 / 会分成哪几块（每块一句话）/
  第一阶段能做什么、暂时不做什么 / 我最快什么时候能看到第一个能看的东西
  + 必须含一段「这个方案最可能怎么失败 + 我建议先防哪一条」（一段话，别列十条）

第 3 步｜查一次 库/索引.md（先查索引，不要整读资产本体）：
  这个项目需要的东西里，有没有已经做过的？列出候选 + 是否适用 + 为什么。
  库是空的就直接说"库为空"，不要凑数。

第 4 步｜按 00_协议.md §7 回答三个必答问题（**第 1 问必须连同"为什么做"一起答——它是阶段③ 复盘唯一的比对基准，事后回想必然失真**），并**补三项**，一并写进 00_根/入口.md
  （三个问题 = 给谁用 / 解决什么；"能看见了"的最小单位；什么绝对不能坏）
  补三项 = ① 成本预期（大白话）② 成功标准（"做成了是什么样"一句话）③ 个人信息清单（会用到你的哪些真实信息——供开发期提醒 + 收尾扫描）

第 5 步｜定**四样基础规划**（必做、不许留空——**定晚了后面每次都要返工**）：
  ① **设计值**：颜色 / 间距 / 字号 / 圆角 / 阴影各一套最简值 → 写进 00_根/复用.md §一
  ② **文案集中处**：所有"对用户可见的文字"→ 写进 `00_根/复用.md` §五（`key | 值 | 用在哪`），不许硬编码散落到各处
  ③ **UI 元素清单**：按钮 / 卡片 / 弹窗 / 加载态 → 写进 `00_根/复用.md` §六（`元素 | 用在哪 | 位置`），只许用表里的，不许每次重写
  ④ **复用清单**：本项目已有件
  值可以粗糙，但必须统一成套。没有把握就给 A/B 两套提案让我挑。
  ⚠️ **这四样必须在第一版之前定**——否则它们会**散落到整个系统里**，事后归拢要花大价钱（**真实教训**）。

第 6 步｜建目录骨架 + 填 00_根/入口.md、00_根/全貌.md（骨架）、00_根/导航.md、00_根/复用.md
  + 写 AGENTS.md（**分发点**——不写则整条自动加载链路失效；**已存在就必须保留，绝不覆盖**）：
    含破竹**绝对路径** + 「开工前先读它，按需往下读」+ **握手规则**（读不到 → 报错并停止）
    （完整模板见 `bootstrap.md` 第 2 步；**若项目是用 bootstrap 起步的，这一步只核对，不重写**）

第 7 步｜停下来等我确认蓝图。我回答「可以」或「不对」，你再结束 session。确认后，在 `00_根/入口.md` 记一句「蓝图已确认 ✅ 进入开发阶段」。

【分寸】
- 必须现在定死：技术栈、目录结构、数据怎么存、工作流程、设计值（定错返工最大）
- 先粗后细：具体功能怎么写、界面拆多细（留给后面长出来）
- 只问业务问题；技术选型你提方案 + 说后果，我拍板
```

**本段产出**：大白话蓝图（给用户）+ 骨架 + `00_根/` 四件（+ `AGENTS.md` / `来源.md`）。
